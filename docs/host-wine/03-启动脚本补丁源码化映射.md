# 启动脚本补丁源码化映射

基线文件：`scripts/palworld-panel-start-fixed-v1.0.36.sh`

## 1. 迁移原则

每一项现有脚本逻辑必须被分类为：

- **保留在启动脚本**：真正属于环境安装和进程入口的职责；
- **迁入 PalPanel 源码**：业务规则、Provider、下载、任务、状态和前端行为；
- **删除**：二进制补丁、编译后静态文件替换、虚假状态或重复实现。

## 3. Windows SteamCMD Workshop 目标流程

```text
面板创建 Workshop 任务
  ↓
取得 steamcmd 操作锁
  ↓
WINEPREFIX=.../wineprefix-steamcmd
  ↓
运行 Windows steamcmd.exe
  ↓
默认 login anonymous
  ↓
失败且存在已验证账号缓存时再用用户名
  ↓
监控日志、输出目录字节和子进程
  ↓
Steam Guard/180 秒无活动/总超时 → 明确失败
  ↓
完整目录安全检查
  ↓
复制到 inspection 临时目录
  ↓
原子切换为可安装检查结果
```

严禁：

- 调用 Linux `steamcmd`；
- 把密码传入命令行；
- 与 PalServer 共用 Wine 前缀；
- 运行 SteamCMD 清理时执行服务器前缀的 `wineserver -k`。

## 4. 启动脚本保留项

源码化完成后，脚本仍需包含：

- 目录创建与权限；
- 便携 Wine 下载和 SHA-256；
- Xvfb、cabextract、winbind、vcrun2022 环境准备；
- Windows SteamCMD ZIP 下载和完整性；
- 两个 Wine 前缀初始化；
- 自定义 PalPanel Release 代理优先下载；
- 版本比较、原子安装、数据库备份和回滚；
- 环境变量写入；
- Launcher 启动。

## 5. 已知脚本问题同步修复

- `diagnose-wine-mods` heredoc 使用 `${WINE_BIN}`，但内部未定义；下一版应补充 `WINE_BIN="${PORTABLE_WINE_CURRENT}/bin/wine"`。
- `BACKUP_DIR=${ROOT}/backup` 与 UE4SS 使用 `${ROOT}/backups/ue4ss` 不一致；统一到 `backup/ue4ss`。
- 当前 `panel_complete` 只检查文件存在，不比较 `.installed-version`；新版必须比较版本。
- 当前升级会直接删除 `APP_DIR`；必须改成 release 目录 + `current` 原子链接或同文件系统 rename。
- 当前启动成功只检查进程 5 秒；必须增加 REST/RCON/可选 Mod 分阶段健康状态。
