# 总体实施计划

## 1. 总目标

在 PalPanel v1.2.1 的 Go + React 架构上完成两类工作：

- **运行时源码化**：把 v1.0.36 启动脚本中的 PalPanel 兼容补丁迁入源码，正式支持简幻欢 Linux + Host Wine + NFS。
- **运营能力扩展**：参考 PalOps Web 的业务设计，重写适用于 PalPanel 的权限、审计、RCON、运营、安全和运维模块。

禁止把 PalOps Web 的 .NET/Vue 模块直接复制进 PalPanel。必须按照 PalPanel 的 Go/React 架构、数据模型和权限体系重写。

## 4. 强制开发闭环

每个工作项必须按以下顺序完成：

```text
读取当前代码与文档
→ 建立/更新测试
→ 实现一个原子变更
→ 运行相关测试
→ 更新文档与 CHANGELOG
→ 更新实施日志
→ git commit
→ git push
→ 检查远端 CI
→ CI 通过后再进入下一项
```

禁止累计多个未推送的大改动，也禁止完成代码后把文档和更新日志留到最后补写。

## 5. 版本规则

### PalPanel 自定义版本

建议开发期：

```text
v1.2.1-hostwine.1
v1.2.1-hostwine.2
...
```

Phase 1 稳定后可转为新的语义化版本，例如 `v1.3.0`。版本号由目标仓库现行规范决定，但必须记录上游基线。

### 启动脚本版本

- v1.0.36 是只读基线。
- 第一处实现修改必须生成 v1.0.37。
- 后续每次脚本行为变化按 v1.0.38、v1.0.39 顺序递增。
- 不覆盖旧版本文件；Release 中同时提供最新版和差异文件。

## 6. 不在首轮做的事项

- 不把 PalOps .NET 应用作为第二个进程嵌入。
- 不把 Vue 编译产物复制到 React 前端。
- 不重写 sav-cli 解析器。
- 不恢复临时存档镜像。
- 不让前端浏览器直接持有 RCON、Palworld REST 或 PalDefender Token。
- 不在未完成 Host-Wine Runtime 前先实现崩溃守护。
