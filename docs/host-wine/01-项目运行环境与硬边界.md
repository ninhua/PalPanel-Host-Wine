# 项目运行环境与硬边界

## 1. 生产运行环境

该项目不是普通的 Linux 原生 Palworld 面板部署，实际环境如下：

| 项目 | 固定或默认值 |
|---|---|
| 托管平台 | 简幻欢容器环境 |
| 系统架构 | Linux amd64 |
| 脚本权限 | 当前脚本要求 root |
| Docker | **没有真实 Docker daemon**；现状由脚本生成 Docker CLI 兼容层 |
| 持久化文件系统 | `/home/container` 位于 NFS 持久化存储 |
| 唯一根启动脚本 | `/home/container/start.sh` |
| 数据根目录 | `/home/container/palworld_win` |
| PalPanel 基线 | 上游 v1.2.1，当前由自定义启动脚本部署 |
| Wine | 便携 Wine 11.13 `amd64-wow64` |
| PalServer | Windows Dedicated Server，经 Wine 运行 |
| X11 | Xvfb，默认 `DISPLAY=:99` |
| VC 运行库 | winetricks `vcrun2022` |
| 存档解析 | `sav-cli`，回环端口 8090 |
| 配种侧车 | `palcalc-bridge`，回环端口 8091 |

未知且不得猜测的项目包括底层 Linux 发行版、内核版本、CPU 核数、内存配额和 NFS 服务端实现。实现必须通过运行时探测处理这些差异。

## 2. 固定目录布局

```text
/home/container/start.sh

/home/container/palworld_win/
├── app/                         # PalPanel 当前版本/发布文件
├── backup/                      # 统一备份根目录
├── cache/                       # 下载缓存
├── config/                      # palpanel.env、标记和密钥目录
├── data/                        # SQLite、索引、快照和业务数据
├── home/                        # SteamCMD/Wine HOME
├── logs/                        # 面板、PalServer、侧车、安装日志
├── run/                         # PID、锁、状态；可重建
├── runtime/wine/current/        # 当前便携 Wine 链接
├── server/                      # Windows Palworld Dedicated Server
├── steamcmd/                    # Windows steamcmd.exe
├── tmp/                         # 临时文件；可重建
├── tools/                       # 环境级辅助工具
├── wineprefix/                  # PalServer 专用 Wine 前缀
└── wineprefix-steamcmd/         # 计划新增：Windows SteamCMD 专用前缀
```

禁止重新引入以下错误路径：

```text
/home/container/palworld-panel
/home/container/palworld_win/start.sh
```

## 3. 服务端与存档硬约束

### 3.1 实际受监督程序

必须监督：

```text
/home/container/palworld_win/server/Pal/Binaries/Win64/PalServer-Win64-Shipping-Cmd.exe
```

不能只监督根目录 `PalServer.exe`，也不能把任意同 Wine 前缀进程误判为服务器主进程。

### 3.2 唯一权威存档目录

```text
/home/container/palworld_win/server/Pal/Saved/SaveGames
```

硬约束：

- 不得恢复 `/dev/shm`、`/tmp` 或双目录镜像存档方案。
- 活动存档不得被存档索引器、差异比较器或前端写入。
- 启动前必须通过 Linux 与 Wine 两层原子替换预检。
- 发现 Prepared 事务时，只能在 manifest、临时文件和期望大小完整一致后受控恢复。
- 正式文件被替换前必须备份。
- 预检失败时拒绝启动，不能回退到系统 Wine 10。

## 4. SteamCMD 最终设计

### 4.1 统一使用 Windows SteamCMD

以下操作统一使用：

```text
/home/container/palworld_win/steamcmd/steamcmd.exe
```

- 安装 Windows PalServer；
- 更新和验证 Windows PalServer；
- Workshop 下载；
- 可选 Steam 账号缓存授权与验证。

完成源码化后，Linux `steamcmd` 不再是强制依赖。

### 4.2 Wine 前缀隔离

```text
PalServer:       /home/container/palworld_win/wineprefix
Windows SteamCMD:/home/container/palworld_win/wineprefix-steamcmd
```

禁止共用前缀，原因包括：

- SteamCMD 自更新可能启动子进程并执行 `wineserver -w`；
- SteamCMD 清理不能终止 PalServer；
- Workshop 必须能在游戏运行时下载；
- 账号缓存、注册表和故障范围必须隔离。

### 4.3 登录规则

- 默认 `anonymous`。
- 不提供默认用户名。
- 不强制启动时登录。
- 不在配置、日志或命令历史中保存密码和 Steam Guard。
- 只有显式配置用户名后才允许尝试复用 Windows SteamCMD 缓存。
- Steam Guard 阻塞时必须终止非交互任务并返回明确状态。

## 5. 默认端口

| 服务 | 默认端口 | 协议/监听 |
|---|---:|---|
| PalPanel | 12559 | TCP，当前脚本取 `SERVER_PORT` |
| Palworld 游戏 | 12559 | UDP |
| Query | 27015 | UDP/TCP 依游戏配置 |
| Palworld REST | 8212 | TCP，仅回环访问管理接口 |
| RCON | 25575 | TCP，仅回环 |
| PalDefender REST | 17993 | TCP，仅回环 |
| sav-cli | 8090 | TCP，仅 `127.0.0.1` |
| palcalc-bridge | 8091 | TCP，仅 `127.0.0.1` |
| 本地 Release 代理（现状） | 18081 | TCP，仅回环；源码化后应删除 |
| Steam API 代理（现状） | 18082 | TCP，仅回环；源码化后应删除或内建客户端能力 |

所有端口均应支持环境变量覆盖。PalPanel 源码必须在启动和保存配置前做端口冲突检查。

## 6. GitHub 下载与代理

统一顺序：

1. `https://v4.gh-proxy.org/<原始 GitHub URL>`
2. `https://cdn.gh-proxy.org/<原始 GitHub URL>`
3. 原始 GitHub URL

适用范围：

- 自定义 PalPanel Release；
- 便携 Wine；
- winetricks；
- PalDefender；
- UE4SS；
- 从 GitHub 获取的 Mod/插件；
- GitHub Release 元数据。

下载器要求：IPv4、HTTP/1.1、连接与总超时、有限重试、最大体积、临时文件、SHA-256、压缩包结构校验、失败后清理 `.part`。

Steam CDN、Palworld REST、RCON 和本机回环请求不得套用 GitHub 代理。

## 7. 启动脚本最终职责

即使补丁迁移到源码，`/home/container/start.sh` 仍必须保留，并负责：

1. CRLF 自修复和严格 Bash 模式；
2. 创建并检查单目录结构；
3. 下载、校验和安装便携 Wine；
4. 初始化 Xvfb；
5. 安装/验证 vcrun2022；
6. 下载、校验和原子安装自定义 PalPanel Release；
7. 下载和维护 Windows `steamcmd.exe`；
8. 初始化两个独立 Wine 前缀；
9. 写入不含凭据的部署配置；
10. 启动 PalPanel Launcher；
11. 在退出时清理只属于面板的侧车进程。

启动脚本最终不再负责业务层 RCON、GM、玩家纪律、审计、Mod 状态、存档索引逻辑或前端文案补丁。
